# Hexfield 326 — Creative memory, selective forgetting and rediscovery

Build 325 gave Hexfield a stable visual personality. Build 326 allows its learned shapes to become **traditions, forgotten ideas, and occasional rediscoveries**, rather than preserving every ancestor forever.

## How memory actually works

**Learn from real accepted paintings.** After each accepted frame, Hexfield checks whether the two inherited form signatures are still visibly represented in the resulting native-resolution artwork. Recurring recognizable pigments and forms establish a streak and a local history. Rejected full-size candidates do NOT update memory. Local independent KEEP/REWORK and negotiated relationships still run normally.

**Forget visibly obsolete characteristics.** A form missing from three consecutive accepted paintings is removed from the active ancestry if it had once genuinely survived. Its automatic pixel inheritance and protected-object influence stop. It therefore can disappear rather than being artificially redrawn forever. This does not delete its entire past: a *tiny, bounded, 12×8 binary silhouette* extracted from the last accepted appearance and its measured RGB pigment and normalized location are kept as a dormant concept.

**Rediscover occasionally, not automatically.** At most once every fourth accepted generation, if there is room for an ancestral form and the old idea has been dormant for at least three generations, Hexfield constructs a small temporary candidate from that real historical silhouette and remembered ink. Its 96 binary occupancy samples are an abstract *record of earlier observed pigment*, not an original full-resolution photograph or a fake exact pixel replay.

**Ask whether it still helps.** The resurrected shape is scored against the actual current artwork using the existing spatial W / φ / H and complexity judgement. A meaningful improvement is mandatory. If the reappearance fails, it is discarded completely; the present canvas remains identical. If it passes, the limited physical patch is added to the candidate and exposed on the same live canvas. It only becomes a renewed permanent ancestry form when the candidate also wins the global composition contest.

**Keep the constraints.** The same current law lock, unchanged dirty tiles and user lettering protections prohibit historical repainting. Changes are strictly confined to one historical footprint; no adjoining region is painted by this feature. Identity safeguards activate again only after a globally winning recall.

**Keep storage small.** At most four dormant silhouettes, two active form IDs and eight recent event summaries are retained. Memory belongs to the root artistic identity; a new root cannot accidentally inherit another painting's memory. The archive is in bounded localStorage metadata, not raster blobs, cloud media or private server uploads. Reset clears this memory.

## Observable creative process

Automatic paintings now expose the real live stages: inherited form and pigment, tentative historical shape resurrection, honest rejection if it scores badly, and successful final KEEP/FORGET/RETURN events. The readout shows active habits, dormant ideas and returns. No new configuration panels, logins, paid image models or background services.

A forgetting counter is **not** proof of human artistic taste: this implementation measures persistence of painted material and evaluates candidate reconstruction with existing numerical aesthetic heuristics. Nor can 12×8 occupancy recover exact pixels lost generations earlier; rediscovery is explicitly a shape-and-colour *reconstruction*.

## Regression tests

Build 326 verifies real accepted-pixel signatures, consecutive disappearance and archive creation, removal from protected living forms, deterministic bounded recovery timing, exact invariance of all pixels outside the resurrected shape, score-gated rejection, winner-only reactivation, malformed archive validation, user-law and sparse-region lockout, text exclusion and ten-generation root continuity. All existing tests remain in the Actions workflow.

# Hexfield build 296 — painting methods can change

## What changed

Build 295 could only choose among six scene types and four moods. Its human-vote
handler adjusted preference counters for those fixed presets; every generated
landscape still ran the same painting algorithm.

Build 296 replaces that architecture with a **bounded evolvable procedure grammar**:

- A landscape's geometry is generated by **expression trees** composed from
  wave, noise, ridges, terraces, dunes, peaks, basins, steps, nonlinear transforms
  and binary combinations. Mutation can replace **an entire subtree**, change
  its operator, or recombine it with another previously kept procedure.
- Additional heritable instructions control layout (valley, escarpment, etc.),
  sky-making, brush mark grammar (hatching, stippling, block strokes, and more),
  planted forms, water, atmosphere and layer count.
- Logo/lettering methods have heritable construction, stroke, join, terminal and
  frame operations. The text is always rendered using readable font outlines;
  arbitrary pseudo-glyph substitution is not part of the grammar.
- **REJECT** does *not* instantly regenerate the same picture with a new seed.
  It records an unsuccessful procedure and proposes explicit counterfactuals:
  **Rebuild the structure / Change the marks / Change the light**. Landscape
  mode adds **Paint somewhere else** when the place is set to Surprise me.
  Each card previews a genuinely different procedure; choosing a card tests
  that method. KEEP promotes the tested procedure into the breeding pool.
- **MUTATE THIS METHOD** makes a descendant from the current work. The standard
  PAINT/DESIGN action draws from retained procedures and fresh inventions;
  part of the search intentionally explores outside the audience's favourites.
- Kept methods, rejections, experiment choices and gene-level preferences
  persist on the device. Human votes containing the actual bounded procedural
  genome are uploaded to the existing owner-private Supabase studio vote table;
  recent own successful methods are recovered on sign-in. Existing artwork
  votes and images are not deleted or altered.
- Cross-visitor taste aggregates (only after >=3 distinct visitors contribute)
  now cover finite method operators, not just the scene and mood selector.
  Individual votes and logo text remain private.

## Honest limitations

- The grammar is **finite**, although it can recombine and mutate nested
  instructions in many combinations. It does not invent arbitrary JavaScript
  functions or new neural-network architectures by itself.
- A binary dislike alone does not reveal **why** something failed. Presenting
  controlled alternate construction methods is an experiment to elicit a
  more informative choice, not proof that the system understood the criticism.
- This update makes *discovering new painting procedures* possible; it does not
  guarantee professional-level visual quality, realism or objective beauty.
- The prior public museum is retained at `/legacy.html`. Stripe is untouched.

## Verification

Run the deterministic genome tests with `node tests/studio-evolution.test.mjs`.
The main site runs Chrome Canvas 2D; extra local integration/render tests were
executed with an in-memory browser document and CPU Canvas 2D before deploying.

Generated recipes are under the existing `hexfield_studio_votes.recipe` limit of
4000 bytes. Rendering respects foreground cancellation and uses reduced quality
for alternatives so mobile devices are not asked to run several full paintings.

## Quick UX test

1. Open Hexfield and let the first landscape finish.
2. Press REJECT. At least three differently constructed alternatives appear.
3. Choose an alternative, then KEEP or REJECT it.
4. Use MUTATE THIS METHOD and observe which instruction changed.
5. Switch to LETTERS, reject a wordmark and compare the new construction and
   stroke grammar alternatives.

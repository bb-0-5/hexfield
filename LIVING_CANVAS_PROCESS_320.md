# HEXFIELD 320 / Actual making on the one canvas

Earlier versions completed the full painting in a hidden calculation buffer, then covered the result with a second, opaque creative-process theatre. Build 320 removes that theatre from the production Rule Studio. The only visible surface is the actual Rule Studio canvas. The process is visible on the production surface rather than represented by a decoration or pre-baked film.

1. While the automatic renderer searches for a method, each genuine 240x150 raster candidate is sent to the same production canvas in turn, partially preserving the prior picture. It is visibly identified as a live candidate sketch, not a finished image.
2. When a candidate wins the real scoring and ancestry tests, the production canvas returns to the accepted parent. The real winner is then constructed progressively, transferring precisely its actual final pixel blocks into the visible painting. Tile order is controlled by the actual captured drawing trace, surviving object identities, changes from the parent, and the physical word region. Mark regions are reconstructed earlier, inherited regions retain their pixels longer, and lettering arrives last.
3. Each construction frame changes the *actual production canvas* rather than covering it with an opaque video overlay. The full accepted painting (including all colour/geometry effects) replaces any incomplete frame at completion, so scoring, persisted artwork and exports are exact. The exported PNG is taken from the real fully evaluated image even if the display is currently partway through a construction.
4. Typing words, pressing Pause, changing input, hiding the page or starting a new pass safely stops old construction, resolves its pending promise and restores the current full accepted frame. Prefers-reduced-motion skips animation and shows the exact finished artwork immediately.

The live stage animation uses existing real image data and procedural mark events; it does not re-run the whole painter or use an image model. It is an incremental presentation of real already-evaluated ink, **not** a claim that the pixel-level creative search itself occurs on the screen in real time. Rendering stages still genuinely execute and present their actual sketches as they become available. No second user-visible canvas, user configuration or cloud cost is added.

Automated tests inspect actual pixels in the one production canvas before, during and after construction, verify deterministic hereditary/letter ordering, exact finished pixel identity, cancellation, first-generation preview inheritance, sparse changes and reduced motion.

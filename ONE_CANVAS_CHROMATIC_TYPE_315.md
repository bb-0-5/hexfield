# Hexfield 315 — One canvas, chromatic type, no mode tabs

## User-facing surface

The home page has one visible \`ruleArtwork\` canvas. There are no RULES / LANDSCAPE / LETTERING / IMAGINE tabs. The usual actions are the word field, PAINT & EVOLVE, PAUSE, KEEP, and REJECT. Painting rules, source selection, manual stepping, print export and generation history are optional collapsed drawers.

Existing legacy DOM and offscreen canvases remain ONLY as internal rendering/source buffers to avoid disabling experimental procedures, historic compatibility or the optional cloud model. They are not alternate user-facing workspaces; there is no embedded competing iframe painting its own frame on the home page.

## New typography application

\`word-surface.js\` is the canvas word painter, not a logo generator or an opaque pre-rendered layer. It uses a glyph occupancy mask only as a starting contour, then changes geometric construction via eight executable styles:

- Inflated counters, upper-heavy split, sheared strata, cutaway stencil,
  chromatic misregistration, faceted terminals, raked letterpress, dual-outline.
- Five construction families including geometric, soft, editorial, mechanical, italic.
- Ink hues are sampled from the actual parent image when available, then rotated by the golden hue angle; otherwise a seeded chromatic palette is invented.
- The existing Rule Studio paint engine generates source-dependent mark texture and the results are deposited within the evolved glyph geometry. The image beneath is kept and the word adapts to locally sampled contrast.
- Word shape and pigment evolve from canvas seed, generation, and inherited mark program. The output reports actual geometry procedure, construction family and palette.

The compositor paints the word on every actual candidate BEFORE W/φ/H judgment. Changing words also refreshes the procedural-letter donor. This is one artwork, not separate logo art imported after evaluation. Mask canvases are internal computational buffers.

## Source collaboration

The existing source bank supplies constructed landscapes, reality, lettering, remembered canvas, experimental archive, optional uploads and stored imaginative paintings. Historical archive artwork can be retrieved from browser-local reference storage; its source lab remains reachable in a separate optional link, but is not an embedded second canvas.

The image-model GENERATE SOURCE action is explicit and uses existing limits. Its result is transferred directly to the main rule painter as a new reference. No automatic image-model generation or extra payment step.

## Safety and validation

No automatic cloud model usage; independent Australian print handoff retained. Tests inspect per-pixel chromatic word results, a collection of distinct procedural font geometries and palettes, existing mixed-source simulation, historic seed-click and reload regressions, and the absence of all user-facing mode tabs and the embedded iframe.
